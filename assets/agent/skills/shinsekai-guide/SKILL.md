# Shinsekai 功能介绍

根据用户要完成的事情介绍功能，先给最短可执行流程。使用用户的语言；界面名称以用户当前界面为准。

## 功能与入口

| 目标 | 设置页入口 | 说明 |
| --- | --- | --- |
| 首次配置 | 新手引导 `/settings/onboarding` | 逐步完成必要配置 |
| 配置模型或凭据 | API 设置 `/settings/api` | 复用已有 LLM、语音等服务配置；不要要求粘贴 API Key |
| 创建或编辑人物 | 人物管理 `/settings/characters` | 设置简介、详细人设、形象和语音资源 |
| 配置场景素材 | 背景 `/settings/backgrounds`、特效 `/settings/effects` | 管理演出资源 |
| 准备聊天模板 | 模板 `/settings/templates` | 配置聊天使用的模板和人物 |
| 管理扩展 | 插件 `/settings/plugins` | 按应用已有流程安装、配置和启用插件 |
| 使用实用工具 | `/settings/tools` | 原实用工具页面；助手顶部有入口 |
| 使用助手 | 导航栏「助手」 | 每个 tab 是独立 Agent session，可新建、切换、发送消息和停止任务 |

路由是定位页面的参考，只有实际存在的导航工具才能替用户打开页面；否则说明点击路径。

## 介绍流程

1. 从用户问题判断目标。信息足够时直接给步骤；仅询问会改变步骤的缺失信息。
2. 解释所需配置及如何验证，例如 API 设置中的连接测试。不能根据「已填写」推断「连接成功」。
3. 区分应用支持的功能、当前助手实际注册的工具、尚未接入的自动操作。以工具定义和返回结果为准。
4. 用户只问一个功能时，围绕该功能回答；需要选择时比较选项的实际影响。

## 助手与角色聊天

助手使用现有 API 设置选择的模型。它与角色扮演的进程、身份和输出规则分开，保持理性及独立判断。
关闭助手面板保留会话与草稿，不等于取消任务；停止按钮请求停止当前任务。整个应用退出时会收尾 Agent。
应用重启后保留历史，恢复的排队任务需要显式继续。模型配置改变后按界面提示应用配置，并新建匹配模型的 session。

当前仅有这些说明性 skills 时，可以介绍功能、分析用户提供的信息、起草人物和插件代码；实际读取日志、保存人物、写入插件、运行检查需要相应宿主工具。不能把说明或草稿说成已完成的应用操作。

## 回答完成

给出用户当前能执行的下一步和可观察的成功标志。若用户进入故障排查，使用 `shinsekai-diagnostics` 的流程。
