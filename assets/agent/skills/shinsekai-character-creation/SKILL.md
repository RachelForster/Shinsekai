# Shinsekai 人物创建

把人物创作与应用保存分开。充分利用用户提供的设定，避免反复询问已说明的内容；仅补充会影响结果的关键缺项。

## 创作流程

1. 确定用途：普通聊天、剧情中的主要或次要人物；整理名字、背景、性格、目标、关系和语言偏好。
2. 写一个有行为依据的人物：欲望、顾虑、能力、局限、冲突、日常习惯及面对不同人的说话方式。不要堆砌互相矛盾的形容词。
3. 生成简洁 `character_brief` 和详细 `character_setting`。简介用于快速识别；详细设定包含背景、行为原则、语言习惯及关系。
4. 根据需求列出形象和语音资源。没有资源生成工具时，只提供描述与准备步骤，不编造文件路径或生成结果。
5. 用户给出了完整创建要求时先给可用草稿，再询问少量可选细节。

## 当前人物字段

应用人物模型包含 `name`、`color`、`sprite_prefix`、`character_brief`、`character_setting`、`sprites`、`avatar_type` 和 `avatars` 等字段。
实际保存工具的 schema 是参数事实来源，不能把下面的创作草稿当作完整可导入配置：

```json
{
  "name": "望月澪",
  "character_brief": "习惯用观察和实验解释怪事的修复师，谈话克制但愿意承认不确定。",
  "character_setting": "负责旧城仪器修复。重视证据，担心自己的疏忽再次伤及他人。遇到未知现象先提出可验证假设；熟人面前会用短句打趣，紧张时反复确认细节。"
}
```

颜色、资源前缀、形象格式和资源列表由用户选择或已有用例确定。尚未创建的图片、语音、Live2D 或 MMD 资源不要登记为已存在。

## 编辑与保存

有查询和保存工具时，先读取现有人物及 revision，再调用已有校验与保存能力。保留用户未要求改变的字段；遇到 revision 冲突先读取新状态并重新核对。
根据工具结果说明保存了什么，以及形象和语音是否就绪。正在运行的角色聊天有自己的配置快照，不能保证保存后立即改变已有聊天。

没有保存工具时，交付可复制的简介、详细人设和资源清单，并引导用户到「人物管理」`/settings/characters` 填写。明确这是人物草稿，不能声称人物已经创建到应用。

## 输出

给出人物草稿或已保存结果、关键创作选择、资源待办和使用方法。人物的性格与台词规则只属于角色设定，不改变通用助手的理性与独立判断。
