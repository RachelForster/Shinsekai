# 聊天 runtime_process 重构计划

日期：2026-10-02。基线：main / 314836b9。工作分支：refactor/chat-runtime-process。

## 目标与问题

`application/chat/runtime_process.py` 当前约 1546 行：进程锁、子进程启动和关闭之外，
还承担历史转换与下载授权、前端状态投影、剧情选择与分支同步、主题读取和命令校验。
可选能力通过修改中央分支接入，调用者也跨模块依赖大量下划线函数。

目标是让进程管理保留稳定、明确的职责，让历史、状态投影、命令和剧情分别拥有自己的实现。
新能力通过应用组合根注册处理器或贡献者接入，而不是继续向进程管理模块增加业务分支。
遵守 PROJECT_STRUCTURE.md；不会把会话所有者下沉到 core 或 sdk。

## 范围与兼容承诺

- 从主干独立重构，不叠加尚未合入的 PR #374/#375，也不包含本机宣传文档。
- 不改变 API 路径、请求/响应字段、WebSocket 命令/事件和历史文件格式。
- 保留进程并发启动锁、Windows 隐藏启动、关闭顺序、初始化失败清理和错误传播。
- 保留命令白名单、输入/附件校验、实验功能权限、历史下载 capability 与过期检查。
- 保留剧情选择、历史落盘、分支同步、快照更新与事件发布的现有顺序。
- 不改变 L2D/MMD 渲染、前端页面、存储 schema、模型资源或插件对外 SDK。
- 仅为旧内部入口提供有退出说明的薄兼容门面；生产调用者迁到明确职责模块。

一侧的接入与编排。两个进程共享命令约定，不共享可变注册表。

## 三类扩展接口

### 命令处理器

- 按命令类型查找唯一处理器，重复注册与未知命令明确报错。
- `submit-option` 的普通文本、story-choice 和 tool-confirmation 使用独立的子类型路由。
- 处理器接收当前动作需要的上下文/端口，不获得任意 HTTP handler 或整套应用 manager。
- 通用转发保留 cmdId、连接检查、关闭标记清理和快照更新；业务校验留在所属处理器。
- 注册集中在组合根；禁止靠模块导入副作用或无限 can_handle 链隐式改变优先级。

### 快照贡献者

- 基础构建器不直接 import 剧情实现。剧情、手机等可选能力提供自己的字段投影。
- 注册时声明字段所有权；拒绝重复所有权、未声明字段和覆盖受保护基础字段。
- 输入为只读的会话/基础快照视图，输出复制合并；读取不能触发业务提交或服务启动。
- 保持原响应的平铺字段，不为了注册接口改变前端协议。
- 字段有意覆盖（如手机接入对应的 wsUrl）由组合根明确授权，不接受任意 update 字典。
- 流式及无实时流的快照都经过同一贡献步骤；必须保留当前两条路径的字段兼容性。

### 生命周期通知

- 区分真正初始化完成和仅 Popen 成功；就绪事件在现有初始化检查成功后发出。
- 通知只携带事件种类、会话标识等必要信息，不暴露 auth token 或可变 BridgeState。
- 可选观察者失败记录日志但不改变核心结果，顺序稳定、支持注销，不在进程锁内执行。
- 必需资源关闭、配置提交、鉴权与历史事务仍是明确流程，不能改成忽略异常的通知。
- 复用现有 sdk/hooks 的语义；不把插件运行时钩子直接当作 bridge 的跨进程生命周期。

## 风险与回退

- 旧测试大量 monkeypatch 私有模块符号：同步迁移 patch 目标，不能用静态别名假装全局
  进程状态可被替换，也不能删除行为断言来通过测试。
- 模块拆分可能形成循环依赖：元数据和历史不依赖组合根；业务依赖窄端口，组合根向下装配。
- 剧情分支同步与实时发送有既定先后顺序：本次不顺便更改事务语义，使用回归测试锁定。
- 分步提交可单独回退；不迁移用户数据。注册接口先只作为应用内部契约，不承诺第三方 SDK。
