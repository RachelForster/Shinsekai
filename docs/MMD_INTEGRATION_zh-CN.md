# MMD / PMX 形象支持

角色编辑器选择 **MMD (PMX)** 后，选择 `.pmx` 入口并导入。导入器会从 PMX 读取贴图引用，仅复制入口和所需贴图到该角色独立的 `avatars/mmd` 目录；聊天舞台和预览都通过现有的 `/api/avatar/file` 受限路由读取文件。模型或贴图缺失、包外路径与路径穿越会阻止导入。

新建状态时，可以为 PMX morph 调整权重、搜索 morph，并选择口型与眨眼 morph。默认优先匹配 `あ` 和 `まばたき` 等常见名称，再依据 PMX 的唇／眼分类选择；不同模型可手动覆盖。保存后，该状态与静态立绘、Live2D 状态一样进入当前格式的资源列表，供聊天按编号或标签选择。语音音量驱动嘴型，眨眼独立运行；状态切换使用共享的平滑过渡。没有对应 morph 的模型不能提供相应能力。

镜头默认与眼睛同高、水平正面朝向，使用跟随镜头方向的柔和正面补光。状态编辑器提供水平旋转、俯仰、缩放、水平／垂直取景滑块，并可恢复默认镜头。镜头随当前状态保存，在预览和聊天中使用相同构图；重置表情不会重置镜头。旧状态未包含镜头参数时自动使用默认视角。眼睛高度优先取左右眼骨骼，缺少时根据头部骨骼或模型高度估算。

当前支持 PMX 模型、贴图、morph 状态、VPD 姿势、VMD 动作、口型同步和自动眨眼；**不支持物理、VRM 或 Blender 源工程直接导入**。MMD 运行时关闭物理模拟，使用正交镜头。Babylon.js 与 `babylon-mmd` 由 npm 锁定并懒加载，仅在使用 MMD 形象时加载；无需 Live2D Cubism SDK。

## 批量导入姿势 / 动作

先导入 PMX 并等待预览加载。在“姿势 / 动作文件”中多选 `.vpd` 和 `.vmd`（允许混合选择，一次最多 100 个），点击“批量导入预设”。每个文件生成一个独立状态，默认用文件名作为标签，沿用当前预览的镜头、基础 morph 与口型/眨眼绑定。预设进入现有列表，可编辑标签/镜头/表情，供聊天按编号或标签选取；查看面板的“播放预设”可重复预览动作，编辑弹窗显示动作第一帧，避免编辑时模型不停运动。

VPD 固定姿势持续保持；VMD 使用 SDK 的骨骼、位移、morph、IK 轨道插值，以 30fps 时间轴播放一次后保持最终姿势。相邻预设切换采用 300ms smoothstep、四元数 slerp 与位置混合，从当前中间姿势接续，未出现在新预设中的骨骼回到原位。同一模型不销毁、不闪空。`restore` 使用动作最终帧而不重播，`edit` 使用第一帧并关闭自动嘴眼；系统减少动态效果下跳过自动播放与过渡。镜头轨道不会接管编辑器镜头。动作先求值，再叠加基础 morph、自动眨眼和语音口型；显式姿势/动作优先于说话头部微动。

动作状态仅新增可选的相对 `motion` 文件引用，旧 morph 状态兼容。后端格式 adapter 校验 VPD（UTF-8 / Shift-JIS）和 VMD 0002 的完整结构、有限参数及与模型实际骨骼/morph 名称的匹配；只含镜头/灯光或完全不匹配的动作不会激活。不同模型的骨骼命名和比例未做自动重定向，部分不匹配轨道由 SDK 忽略，跨模型动作仍可能需要手动调整。

共享导入服务负责文件授权、暂存复检、独立受管副本与单次配置提交；任何文件校验或配置持久化失败都会回滚整批。原始文件保持不变，重名文件各有独立目录。引用通过现有 `/api/avatar/file` 读取，`.char` 导出/导入携带动作文件，不放宽公共媒体路由。共享 UI 只读取格式描述符的 `stateExtensions` 并复用多选 `FilePicker`、资源列表和通用 repository；文件解析与播放均留在 MMD adapter，已有插件无需实现可选的 `import_state` 方法。

完整动作校验发生在导入、保存和 `.char` 包校验阶段，VPD 按原文本匹配位置推进，不反复复制剩余文本。每个保存状态旁有宿主生成的 `.dependencies.json` 索引，绑定模型文件信息、状态摘要和已验证依赖的路径／文件信息。资源授权只读取有大小上限的索引及状态 JSON、检查文件信息，不重新读取 VPD/VMD 内容，也不长期缓存整批骨骼／morph 名称。外部角色包中的索引不作为信任依据，导入时重新校验并生成；模型、状态或依赖被修改后需重新保存／导入。较早试验版没有索引的模型状态可通过 `.char` 导出再导入补齐；状态 JSON 的格式保持兼容，但不再在资源请求中隐式迁移。

批量预设仅复制一次到 `states/.batch-<随机标识>/`，写入 `.pending-import` 标记并持有进程级文件锁。配置原子提交成功后才发布这些路径并移除标记，不把未提交批次复制成普通 `states/` 目录。bridge 启动时清理有标记、无活动锁且未被持久配置引用的批次；已提交的状态及其动作依赖会保留，无法确认配置时延后清理。导出排除尚未提交的批次；无标记的历史目录不会自动删除。

说话时默认叠加轻微的头部运动，复用实际播放语音的强度信号。共享 `TalkingHeadMotion` 负责渐入、渐出和慢速错峰节奏，MMD adapter 自动识别可旋转、无固定轴限制的 `頭/head`、`首/neck` 骨骼及英文别名，沿头颈父子链分配小幅旋转；缺少绑定时安全跳过，不转动整个模型或镜头。微动是 MMD 骨骼求解的临时输入，在 before/after physics 两个阶段后恢复原始局部姿态，不累积、不进入保存状态。编辑模式、系统减少动态效果设置和已选中的显式骨骼动画会停用微动；暂停或结束语音时平滑归位。无需新增依赖或修改角色卡、状态 JSON 与聊天事件。

本地真实模型冒烟测试通过 `SHINSEKAI_PMX_MODEL` 指定用户有权使用的 `.pmx`，启动 Vite 开发服务器后执行 `pnpm exec playwright test e2e/mmd-local-smoke.spec.ts`。测试从本地模型及贴图读取，不将它们放入仓库或发行包。使用第三方模型时仍应遵守该模型自己的授权与分发限制。
