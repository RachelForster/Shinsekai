# 托盘与主窗口关闭

点击主窗口关闭按钮或使用 Alt+F4，默认显示与主程序配色一致的确认弹窗：

- **退出程序**：结束程序，聊天和日程提醒停止。
- **最小化到托盘**：隐藏主窗口，程序继续运行，日程提醒照常投递。
- **取消**：保留窗口；按 Esc 或关闭弹窗也表示取消。

勾选“记住我的选择”后，退出或驻留托盘的选择会保存到桌面配置目录的
`background.json`，下次关闭主窗口直接执行。取消不会记住任何选择；保存失败时保留弹窗，
可以重试或取消。旧版配置没有记忆标记，升级后首次关闭也会询问。

在“系统设置 → 托盘与日程 → 关闭主窗口时”可随时选择“每次询问”、
“最小化到托盘”或“退出程序”，点击保存生效。“最小化主窗口到托盘”仍单独控制最小化按钮。

系统托盘不可用时禁用驻留选项；之前记住的驻留选择会回到询问，避免隐藏后无法恢复。
托盘菜单中的“退出 Shinsekai”是明确退出操作，直接结束程序。聊天窗口仍沿用原来的关闭行为。

关闭请求、可用性检查和配置持久化由 Rust 桌面壳负责。前端确认弹窗不依赖 Python 后端启动，
并会在挂载时读取尚未处理的关闭请求，以覆盖主窗口刚启动时的关闭操作。

## 自启动与日程管理

在“系统设置 → 托盘与日程”中打开“登录系统时自动启动”，Shinsekai 会在当前用户登录后启动并检查日程。
开关立即生效，状态读取自操作系统启动项；关闭开关会移除启动项。此功能使用 Tauri 官方
[Autostart 插件](https://v2.tauri.app/plugin/autostart/)，不会让电脑开机或从睡眠中唤醒。

“查看所有提醒安排”直接打开完整日程列表。待提醒日程可以编辑标题、提醒内容、人物、下次提醒时间和重复频率；
列表也显示已完成、已取消和已错过的日程，所有记录均可删除。删除日程会使尚未提交投递的领取失效；
已经收到的卡片可单独标记已读。日程仍由聊天中的 `manage_reminders` 工具创建。

`character_name="*"` 表示每次到期时从当前已有角色中随机选择一个；每天或每周重复时重新选择。
正文应描述要提醒的事情，到期后按所选角色生成台词和语音。没有已配置角色时无法创建随机日程；
之后角色库变空时会等待角色恢复，并沿用原有 30 分钟补发范围。

原先启用的睡眠提醒会自动迁移为普通的每日随机角色日程，保持原时间和已投递记录，之后可在列表中编辑或删除。
迁移具有独立的完成标记，即使迁移中断并重试，或用户删除了迁移后的日程，也不会重新创建。
所有提醒在程序完全退出后停止；最小化或驻留托盘时仍会执行。

## 角色台词和语音

角色工具创建的日程到点后，先显示原有文字，随后使用当前配置的 LLM，
根据该角色的设定和本次日程生成一句台词。提醒复用聊天的 `DialogTemplateSection`，
在 `ai/llm/template/reminder.py` 中追加提醒约束，并设置 `max_dialog_items=1`。
输出仍是原来的 `{"dialog": [{"character_name": "角色名", "speech": "显示台词", "translate": "语音翻译", "sprite": "-1"}]}`。
界面和语音语言不同时生成 `translate`，相同时沿用不含翻译的普通 dialog 格式。

生成使用原有 `LLMManager` 的格式修复和 `LlmResponseStreamParser` 解析。
每次提醒使用独立的单轮上下文，仅接受指定角色的一条发言，关闭工具调用、旁白、选项和状态输出。
语音复用 `DefaultTtsGenerationStrategy` 与 `TTSManager`：优先使用 `translate`，
缺少翻译时走原有的文本清理、翻译和人名读音处理。每条提醒合成一个独立语音文件。

语音通过当前 TTS 服务合成，沿用角色的模型、参考音频、语速和音量配置；无需打开聊天。
服务未配置、超时或生成失败时保留文字提醒。冷启动服务可能需要等待，文字投递不受影响。
退出整个程序后不再投递提醒，驻留托盘时仍可生成和播放。

小卡片只增加静音和重播按钮。每次到点的语音自动播放一次，多条语音依次播放。
关闭卡片或按 Esc 会停止播放；语音生成完成也不会重新打开已隐藏的卡片。
静音选择会保存，取消静音不会补播错过的提醒，可以手动重播。

语音文件使用独立文件名保存在 `cache/reminder_audio`，成功合成时清理七天前的缓存。
聊天与提醒共用 TTS 服务时，通过跨进程锁串行切换角色模型和合成，避免串音色。
