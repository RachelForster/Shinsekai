# VRM / VRMA 本地接入

本实现已同步 v2.7.0 主线模型形象接口，VRM 与 MMD 各自使用独立适配器和按需加载的前端依赖。

## 使用

1. 在人物编辑页保存角色，然后把“形象类型”设为 **VRM**。
2. 选择本机 `.vrm` 入口并导入。当前只接受自包含的 VRM 0.x / 1.0 GLB；外部纹理或缓冲区 URL 会被拒绝。
3. 点击“新建状态”调整镜头、表情、人形骨骼、口型和眨眼绑定，并保存到该角色的 VRM 资源列表。配置视觉服务后，可以用“AI 标注当前预览”填充标签草稿。
4. 要直接导入动作，在“姿势 / 动作文件”中选择一个或多个 `.vrma`，点击“批量导入预设”。每个动作使用当前预览状态的表情与姿态，文件名成为标签；一次最多 100 个。可在状态编辑器中移除动作引用，也可通过“播放预设”预览。

旧状态继续读取 `expressions`、`bones`、`motion`，新状态可额外保存 `camera`、`mouthExpression` 和 `blinkExpression`。骨骼使用规范化人形骨骼局部 XYZW 四元数。VRMA 播放一次后保持末帧，编辑时显示首帧，恢复时显示末帧。口型默认匹配 `aa`，眨眼默认匹配 `blink` 或一对左右眼表情。

连续对白的动作按收到指令的顺序排队。当前动作完整播放结束后，下一动作从第一帧开始播放，包含自身的待机、进入、主体和退出部分。加载较慢的动作会保留队列位置，失败的动作跳过后继续处理后续动作。骨骼姿态、表情和镜头在对应动作实际开始时一起更新，口型始终跟随正在播放的语音。

编辑器的“播放预设”按钮可立即从头重播。编辑、重连恢复、历史回放和模型卸载会清空待播动作，恢复模式仍显示末帧。正常连接中重复的同一状态快照保留播放进度。旧预设中的 `motionTiming` 继续兼容读取，排队播放使用完整动作。

## 文件与兼容边界

- 模型、保存的状态与动作复制到项目受管目录；资源服务只开放当前角色配置引用及其经校验的依赖，不能借模型接口任意读取包内或本机文件。
- 旧预览项目可以运行 `python tools/migrate_vrm_preview.py <旧项目目录> <新项目目录>` 复制到新版，模型、状态和动作进入新版受管目录并重新建立依赖索引。启动器可通过 `--project-root` 选择迁移后的目录。
- AI 标签生成需要已配置的视觉服务，结果在保存状态后写入角色配置。
- 预设删除和历史资源授权由独立的 PR #428 提供，本 PR 不重复实现；VRM 使用同一套通用模型资源接口。

后端边界测试见 `test/unit/core/media/test_vrm.py` 和 `test/unit/application/characters/test_model_assets.py`；前端状态与编辑器测试见 `frontend/src/test/`，真实模型浏览器测试见 `frontend/e2e/vrm-renderer.spec.ts`。
