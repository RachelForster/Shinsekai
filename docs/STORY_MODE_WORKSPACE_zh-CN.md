# 剧本创作工作区

基于 #343 的简单节点协议。用户的目标是把一个故事起点变成可以开始游玩的剧情，
因此页面围绕三个问题组织：我要生成什么、生成到哪里了、现在能否运行。

## 用户路径

1. 在「聊天模板」顶部选择「正常模式」或「剧本模式」。标签支持方向键和 Home/End，
   已访问面板保持挂载，切换不会丢掉未保存的正常模板或打断生成任务。
2. 首次使用剧本模式时，点击「启用剧本模式」保存现有总开关。设置失败时仍保留入口，
   不启动生成。
3. 选择「创作新剧本」，直接选择人物与背景；剧情梗概选填，不依赖模板。
   人物卡片和全选操作复用正常模式的 `CharacterPicker`，主次要人物沿用同一套
   `CharacterRoleStatus`、`PrimaryCharacterDialog` 和角色更新逻辑。主要人物使用完整设定，
   次要人物使用简介，具体人物与背景系统提示词由普通模板生成器生成。
   剧本中的人物和地点只提供叙事参考，不再附加人物白名单、固定阵容或背景目录限制。
4. 逐步查看「故事基础」「人物列表」「剧情节点」。阶段完成后可展开内容，
   完整原始数据放在第二层折叠区域。中断与生成错误由后台自动恢复，无需点击继续。
5. 剧本图展示实际生成的节点、分支、回环和结局，点击节点查看剧情要求、地点、
   轮数限制及跳转条件。支持缩放与区域滚动，小屏幕不会撑宽整个页面。
6. 通过校验的产物可以「运行剧本」：使用剧本内保存的人物和背景初始化一份新聊天历史，
   再将生成的 draft 接到故事运行时，最后打开聊天画面。已有聊天运行时会要求先结束，
   附加失败可重试且复用本次初始化结果，不重复创建历史。
7. 重新生成会清除所选阶段及后续阶段的展示和运行资格，等待新产物通过校验。
   页面使用本地存储保留任务 ID，兼容旧会话存储；返回或刷新时自动读取后台任务。
8. 「已有剧本」列出保存的剧本。有历史记录时从已保存节点继续游玩，也可重新开始。

## 自动续跑与 LLM 纠错

后台的 `StoryGenerationRecovery` 为每个任务维护一个执行者，创建请求、页面轮询和
重复连接共享同一执行者。应用启动时扫描 `.generation/*/task.json`，自动恢复排队中、
执行中或失败的任务；已成功和用户明确取消的任务不会自动重启。关闭页面不停止后台。

1. 恢复前核对已完成阶段的产物哈希。产物缺失或损坏时，从最早损坏的阶段重做；
   正常阶段保留。不完整的 draft 会丢弃，并从有效产物重新组装。
2. 模型输出先经过 JSON 和阶段结构检查，再组装剧本，执行既有解析器、编译器和
   路径模拟检查，包括节点跳转、人物配置、可达结局和秘密泄露检查。
3. 错误代码、位置、诊断及失败输出（最多 12,000 字符）保存到检查点，并随下次
   请求发送给模型。JSON 或阶段结构错误直接重做当前阶段；编译或模拟错误优先
   使用受限补丁修复，补丁不能改写用户保存的模板启动设置和受保护字段，也不执行模型代码。
4. 每轮最多尝试 3 个补丁；整轮未通过，或连续 3 次补丁输出无效，自动重写相关阶段。
   人物诊断从人物阶段重写，其余通常重写剧情节点，再重新编译和模拟。累计尝试数
   不作为停止条件，持续到检查通过或用户取消。
5. 模型连接失败、超时等采用 2 至 60 秒退避重试；配置缺失至少等待 30 秒。
   修复配置或恢复网络后自动续跑。待重试时间、次数、最近错误会显示在页面上；
   模型内容错误默认间隔 2 秒再次纠错。所有模型调用（包括失败调用）计入用量估算。
6. 取消立即落盘。正在进行的模型请求可能要等服务商返回，但返回内容不再推进阶段，
   等待中的重试也会停止。磁盘不可写等存储故障无法由 LLM 修复，会报告错误并保留
   已有检查点，不通过额外模型请求尝试修复磁盘。

只有通过检查的任务才标记为成功并提供游玩入口。模型或网络长期不可用时，任务会
等待重试，不会把未经检查的剧本标记为可游玩。旧 resume API 保留兼容用途，页面不再提供手动续跑按钮。

## 代码职责

- `features/template-workspace`：模式标签与访问状态，不包含生成业务。
- 页面与分区复用 `page`、`section` 样式；控件复用 `Button`、`Select`、`TextArea`、
  `SegmentedTabs`。专属 CSS 仅负责工作区嵌入布局、生成阶段和剧本图。
- `features/story-generator/state`：任务跟踪、恢复、取消与重新生成。
- `features/story-generator/components`：设置、阶段内容、校验结果和启动交互。
- `features/story-generator/graph`：有限节点集合的布局与交互，不解释跳转条件。
- `entities/story` 和 `shared/platform`：类型与平台传输；浏览器预览实现独立存放。
- `application/story/generation_preview.py`：读取任务的已完成产物；图优先采用修复后的 draft。
- `application/story/generation_recovery.py`：后台恢复、退避、阶段重写和单任务执行协调。
- `application/story/prompt_runtime.py`：通过既有聊天 hooks 附加节点提示、判断剧情进度。
- `frontend_bridge_core/routes/story_routes.py`：按任务 ID 暴露预览，复用现有故事启动接口。

## 普通模板上的剧情扩展

剧本对话直接走普通模板聊天链路，不再拦截用户输入调用 `SceneOrchestrator` 生成对话。
启动时调用普通模式的 `_generate_system_template_for_mode`，复用人物、背景、媒体索引、
JSON 输出格式及插件输出协议。workflow、CG 开关、选项等优先沿用普通模式当前保存的设置，
读取设置时不生成或写回普通模板。原模板生成器、立绘渲染器和 workflow 执行器保持原样。

`BEFORE_CHAT` 仅在请求副本中添加当前节点的剧情要求、已进行轮数和衔接条件，不改写基础
系统提示词、工具列表、生成参数或聊天历史。普通模型仍输出原来的 `dialog` 格式，不能要求
它额外输出 `nextNodeId`、人物白名单或另一套媒体格式。

普通回复完成后，`MESSAGE_ADDED` 使用独立的状态判断请求分析已发生的对话，得到下一节点
或留在原地。判断响应只用于推进状态，不进入聊天历史或渲染队列。非法节点、无效判断和
判断期间的回退/分支切换不会覆盖已生成的普通回复；工具中间轮次不推进剧情。
节点状态保存到原有故事存档，下一次请求自动读取最新状态再注入相应提示。历史旁的
`story-prompt-binding.json` 负责把普通聊天与剧本关联，恢复游玩也沿用相同机制。

故事状态事件只更新 `story` 信息，不替换聊天的立绘、背景、选项、数值或历史记录。
节点地点不直接触发背景切换，剧本人物列表不控制实际说话者；这些继续由普通模板输出和
正常媒体处理决定。剧本编译仍校验节点连接和结局可达性，不把媒体目录当成剧情地点白名单。

## 验证范围

自动测试覆盖模式切换和草稿保留、共享人物选择、主次要人物、自动恢复、阶段与图展示、
校验失败禁用运行、启动顺序、已有会话保护、附加失败重试、开关写入失败、
回环和孤立节点布局、预览路由和重生成后的产物失效。后台测试另覆盖坏 JSON、
阶段格式错误、无效补丁、修补无效后的自动重写、网络超时、重复请求、损坏检查点、
应用重启以及执行中和退避期间取消。
浏览器以预览数据检查桌面与手机尺寸。真实模型调用与语音服务由用户配置提供，
本次验证没有向付费模型发起创作请求。
