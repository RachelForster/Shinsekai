# 连接 ComfyUI：秋叶整合包、桌面版与官方便携版

新世界连接的是 **运行中的 ComfyUI 服务**。启动器负责启动 ComfyUI，新世界通过标准接口提交工作流、上传参考图和获取结果。秋叶等整合包只要提供标准 ComfyUI 服务，就可以使用同一套 API 工作流；无需把整合包改成官方便携版，也无需让新世界代替它的启动器。

**第一次使用按这个顺序：启动 ComfyUI → 在网页跑通工作流 → 在新世界保存连接 → 先生成一张立绘。** 后续使用只需保持 ComfyUI 运行，不用每次重新试跑工作流。

## 1. 先用自己的方式启动

| 安装方式 | 怎样启动 | 新世界里的自动启动 |
| --- | --- | --- |
| 秋叶／绘世等整合包 | 使用整合包自带启动器，等 ComfyUI 网页打开并可用 | 关闭，不用填安装目录或启动命令 |
| ComfyUI Desktop、手动 Python、其他环境 | 沿用原本能正常启动的方法 | 关闭 |
| 官方 Windows 便携版 | 可自行启动，也可让新世界代为启动 | 可选，见下文 |
| 另一台电脑上的 ComfyUI | 先在服务端启动，确保当前电脑可访问它的 ComfyUI API | 关闭 |

启动器的文件名和参数随版本变化，应按整合包自己的说明使用。秋叶整合包入口可从[作者的下载导航](https://www.bilibili.com/read/cv31254871)查找。

确认浏览器里的 ComfyUI 网页能用，记下其**服务根地址和实际端口**。例如网页在 `http://127.0.0.1:8188/`，新世界也填 `http://127.0.0.1:8188`；如果是 `8189`，就填 `8189`。不要照抄别人的端口，也不要填写 `/prompt`、`/history`、浏览器的查询参数、工作流路径或启动器路径。反向代理部署时保留实际 API 服务的路径前缀。

地址是 ComfyUI 后端的地址，不是单独托管的前端网页或登录页面。当前适配器使用标准自托管 API，不会为需要额外鉴权的代理自动填写凭据。

## 2. 先在 ComfyUI 网页运行工作流

把**画布版工作流 JSON** 导入 ComfyUI，按该工作流安装模型和节点，填写提示词、上传参考图，先成功生成一次。API 形式相同，只表示连接协议相同，不能保证不同整合包里的内核、节点、模型和显卡环境相同。

使用新世界附带的 H3 工作流：

1. 在“立绘智能生成 → 模型与工作流”点击“打开工作流文件夹”。
2. 把 `minimax_h3_i2v.json` 导入 ComfyUI（无参考图用 `minimax_h3_t2v.json`）。
3. 按“H3 模型下载页”和“H3 安装教程”放置模型，上传自己的参考图，然后运行。
4. 若提示缺少 `MiniMaxH3…` 原生节点，检查并更新实际启动的 ComfyUI 内核；仅更新启动器或界面不一定更新内核。遵循所用整合包的更新方法。

模型文件、放置目录、显存设置及立绘操作见[立绘与 H3 指南](CHARACTER_SPRITE_GENERATION_zh-CN.md)和[ComfyUI 官方 H3 教程](https://docs.comfy.org/tutorials/video/minimax/minimax-h3-native)。新世界不会自动安装这些模型和节点。

## 3. 准备 API 工作流 JSON

两种文件都是 `.json`，用途不同：

| 格式 | 内容大致长什么样 | 用在哪里 |
| --- | --- | --- |
| 画布版 | `{"nodes": [...], "links": [...]}`，包含节点位置和连线布局 | 导入 ComfyUI 网页 |
| API 版 | `{"131": {"class_type": "…", "inputs": {…}}, …}`，以节点 ID 为键 | 新世界的“API 工作流 JSON” |

自定义工作流在 ComfyUI **文件 → 导出(API)** 保存。旧版可能需要先在设置中开启开发者模式，再使用 **Save (API Format)**。仅修改文件名或扩展名不能转换格式。参见[官方导出说明](https://support.comfy.org/articles/2703236295-comfy-api-deploy-your-comfyui-workflow-as-an-api)；本文使用本机自托管服务，无需购买云端 API。

附带 H3 已有 `minimax_h3_i2v_api.json` 和 `minimax_h3_t2v_api.json`，不需要自行转换。若修改了画布节点或模型选项，应重新导出对应 API 版，并检查新世界里的节点 ID。

## 4. 在新世界填写连接

进入 **API 设定 → 图像生成（T2I）**：

1. 本机服务选“本机 ComfyUI”；其他电脑或代理地址选“自定义”。T2I 服务商选择 `comfyui`，不是 H3 模型名。
2. **秋叶／绘世及其他自行启动的环境，关闭“由新世界自动启动官方 Windows 便携版”。** 不用填目录，也不会调用整合包的启动命令。
3. 填写刚才确认的服务根地址，点击旁边的“检测连接”（无需先保存）。检测只读取系统状态，不会自动启动服务或提交生成任务；结果会区分超时、不可达、需要鉴权以及非 ComfyUI 页面。连接成功后，选择当前电脑上的 **API 工作流 JSON** 文件。
4. 展开“高级节点映射”，按此工作流配置提示词、输出和参考图节点 ID。节点 ID 随工作流变化，不是通用常数。
5. 保存配置，回到角色的“立绘智能生成”，先生成一张，确认正常后再批量生成。生成期间保持 ComfyUI 运行。

检测连接成功仅代表标准 ComfyUI 状态 API 可用，不代表工作流、H3 节点、模型或显存配置已经验证。修改地址后旧检测结果会清除，需再次检测。检测从新世界后端发起；远程使用新世界时，`localhost` 指运行新世界后端的那台电脑。

内置 H3 的具体映射：提示词 `131`，输出 `92`，参考图 `114`；`text_only_workflow_path` 选择 `minimax_h3_t2v_api.json`，`generation_timeout` 可设 `2400`。这些值仅适用于随附工作流，完整参数见[H3 配置表](CHARACTER_SPRITE_GENERATION_zh-CN.md#2-在新世界连接同一个服务)。

“补全缺失的默认值”会保留已设置的本机端口和节点 ID；通用默认节点值并不适用于所有工作流，尤其不能代替上面的 H3 映射。

### 可选：自动启动官方 Windows 便携版

只有希望新世界代为启动官方便携版时才开启开关，选择同时包含下列文件的**根目录**：

```text
ComfyUI_windows_portable/
├─ python_embeded/python.exe
└─ ComfyUI/main.py
```

端口由 API 地址读取；`startup_args` 只用于这一启动方式。秋叶、Desktop、虚拟环境等不同目录结构不使用此功能。服务已运行时会直接连接，不会再次启动。旧配置中已填写便携版目录且未指定启动模式的，保留原先的自动启动行为；可随时关闭开关改用自己的启动器，已保存的目录会保留。

## 遇到问题先看这一层

| 现象 | 怎么处理 |
| --- | --- |
| 秋叶启动器打不开，ComfyUI 网页也无法使用 | 先按整合包的启动日志和说明修复；此时还没有可供新世界连接的服务。 |
| 新世界提示找不到官方便携版目录 | 秋叶／绘世、Desktop 等关闭自动启动，用自己的启动器启动；官方便携版检查根目录，不要选择内层 `ComfyUI`。 |
| 网页可以打开，但新世界无法连接 API | 确认实际地址和端口，检查该地址的 `/system_stats` 是否返回系统信息 JSON；404、登录页、普通网页均不是可用的 ComfyUI API。 |
| 提示“画布工作流，不是 API 格式” | 重新导出(API)，或选择内置 `_api.json` 文件。 |
| 缺节点、模型名称无效、执行时报错 | 回到同一个 ComfyUI 先运行同一工作流，检查实际内核版本、节点、模型及其文件名。API 一致不代表这些依赖齐全。 |
| 提示词或输出节点不存在 | 检查所选 API JSON 中的 ID；更换工作流后同步修改节点映射。 |
| 服务能连上但生成超时／显存不足 | 查看 ComfyUI 日志，先单张试跑，调整分辨率和时长；首次模型加载较慢时增加生成超时。 |

接口依据：[ComfyUI 自托管 API 文档](https://docs.comfy.org/development/comfyui-server/comms_routes)。新世界使用其中的 `/system_stats`、`/prompt`、`/upload/image`、`/history` 和 `/view`。
