# 聊天与模板

左侧「聊天」进入统一聊天列表。普通聊天与剧本聊天按存档分别展示，显示类型、
人物、名称、最近消息和时间。每条记录都提供设置、重命名和删除入口。
点击「继续聊天」恢复该条记录；重命名不会移动文件。

点击「新建聊天」先在弹窗填写聊天名称，选择普通聊天或剧本聊天，再进入对应配置。
聊天名称独立于模板名称；配置页仍可修改名称。普通聊天复用模板编辑器，剧本聊天
优先展示已有剧本库，也保留创作新剧本的入口。页面不再叠加最近/新建和模式标签页。
每次「创建并开始」都会新建独立记录，即使人物、模板完全相同。
已有剧本在此处也会开始新的游玩；继续某次游玩的进度应从聊天列表进入。
删除需要确认，会清理该记录的消息、分支和剧本进度，保留人物、模板、原剧本及无关文件。
初始化期间或该聊天仍在运行/关闭中时拒绝删除，避免后台写回使记录重新出现。

## 模板与会话设置

模板是可复用的创建配置，一份模板可以创建多段聊天。每段新聊天保存自己的启动配置，
包括场景、生成的提示词、所选人物和资源选择模式。修改公共模板不会自动改写旧会话。
普通聊天和剧本聊天的「聊天设置」复用现有模板编辑器。聊天窗口的设置菜单也提供
「编辑本次聊天」，在弹窗中修改人物、模板及资源配置，关闭弹窗不会停止聊天。
「应用并继续」会重新加载原记录，明确使用编辑后的提示词；已有消息、分支和剧本进度保留。
正在回复、播放语音或等待批量消息时会拒绝应用，其他正在运行的聊天也不会被关闭。
剧本聊天编辑的是本次游玩的启动配置，剧本内容仍由原有剧本编辑器管理。
现有立绘解析及资源选择策略保持原样。

## 代码职责

- `frontend/src/features/chat-workspace/`：聊天工作区、聊天列表、类型标签和当前聊天设置弹窗；组件样式与组件放在一起。
- `frontend/src/features/template-editor/`：可复用的模板与启动配置编辑器，由聊天工作区调用。
- `frontend/src/features/story-generator/`：剧本库、创作与启动交互。
- `frontend/src/entities/chat/`：聊天数据访问和标题规则，不承载业务 UI。
- 对应测试放在 `frontend/src/test/features/chat-workspace/` 和 `frontend/src/test/entities/chat/`。

## 存储兼容

- 新建记录使用 `chat-时间戳-随机后缀`，不再以人物和模板内容计算身份。
- 老 hash 目录和旧 `.json` 文件自动发现，保持原路径；已迁移的旧文件别名不重复展示。
- 聊天名称、启动配置存于模板目录同级的 `config/conversations/`，以规范化历史路径的
  摘要作为元数据索引。列表不会发送完整提示词，准备启动时才读取所选配置。
- 旧普通记录缺少完整启动配置时，显示「设置并继续」，首次恢复需要确认人物、模板和
  资源选择模式。不会套用最近打开的另一段聊天配置。
- 剧本存档按各自的 `story-v2.json` 与 `story-prompt-binding.json` 关联原剧本，
  同一剧本的多次游玩分别展示；原剧本删除或改变而不再匹配时，沿用原有恢复校验。
- `/settings/launch` 旧入口重定向到统一聊天工作区；`?mode=story` 深链接继续有效。

外部历史只会在用户明确使用该路径启动后进入元数据索引，不扫描项目外的任意文件。
删除或移走聊天历史后，对应元数据不会使该条空记录重新出现在列表中。
