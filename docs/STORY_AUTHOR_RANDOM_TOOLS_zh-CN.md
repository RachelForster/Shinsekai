# 剧本生成阶段的随机工具

生成剧本的 LLM 可以调用 `random_sample`（不放回抽样）、`random_shuffle`（洗牌）、
`random_roll_dice`（掷骰）、`random_assign`（按数量分配标签）。随机结果由程序计算，
工具结果返回后，LLM 继续输出原有阶段的 JSON，由原有编译和纠错流程验证。

例如在创作要求中写“将四名人物随机分为一名狼人和三名村民，并围绕分配结果创作剧情”，
LLM 可以调用：

```json
{
  "name": "random_assign",
  "arguments": {
    "requestId": "initial-role-deal",
    "participants": ["alice", "bob", "carol", "dave"],
    "labels": {"wolf": 1, "villager": 3}
  }
}
```

这里的名字是普通标签和参与者 ID，工具不依赖狼人杀规则，也不限制剧本可用的人物或背景。
本期随机发生在**创作阶段**：写入剧本的身份是该剧本的固定事实，重新游玩同一剧本不会自动重新分配。
模型是否发起调用由其判断；提示词要求需要随机决定时使用实际工具结果。

## 代码归属

| 位置 | 职责 |
| --- | --- |
| `core/randomness.py` | 参数约束与随机算法，不依赖 LLM、游戏或存储 |
| `application/random_requests.py` | 宿主拥有的作用域、随机种子、幂等执行和保存接口 |
| `ai/tools/random_tools.py` | 显式 JSON Schema 与工具名称到操作的转换 |
| `ai/tools/call_protocol.py` | 归一化 OpenAI 兼容与 Claude 的工具响应 |
| `ai/llm/template/story/author.py` | 用 Section 拼接作者规则、可选随机工具说明和请求 JSON |
| `application/story/author_tool_loop.py` | 剧本作者专用工具循环、取消和调用预算 |
| `application/story/generation.py` | 为生成任务绑定结果存储，并接回阶段生成和编译流程 |

复用已有的 `ai/tools` 目录。工具没有注册到普通聊天的全局工具列表，生成调用不进入聊天历史。
模板生成、立绘显示和游戏 workflow 不变。

## 重试、恢复与边界

- 每个生成任务保存独立的 `random-requests.json`，先原子保存种子，再原子保存决定，保存成功后才返回结果。
- 同一 `requestId` 与相同参数返回原结果；同一 ID 改用不同参数会得到可纠正的工具错误。
  同一决定在保存中断后重试也使用相同种子计算。
- 后续阶段、编译修复和任务恢复通过 `resolvedRandomRequests` 获得已提交的决定，不携带种子。
  提示词要求沿用既有结果；ID 由模型命名，因此不能阻止模型把同一语义决定换名重抽。
- 参数错误、未知工具和无效参数 JSON 作为工具错误反馈给模型。文件保存失败直接中断，不发布未保存的结果。
- 每次阶段或修复调用最多 8 轮 LLM 请求、24 次工具调用，最后一轮禁用工具；每个任务最多 128 个随机决定。
  对支持 JSON 模式的适配器，即使模型提前结束工具调用，也会关闭工具并用同一请求和已执行结果进行一次 JSON 收尾。
  收尾不把工具轮次的临时正文加入上下文，且包含在 8 轮上限和成本估算内；不支持 JSON 模式的适配器保留原有正文解析路径。
  每次模型请求均计入生成成本估算，模型轮次之间和工具执行前检查取消。
- 仅允许这四个随机工具；不开放文件、网络、代码执行或全局聊天工具。

## 预留开局执行接口

未来开局执行器可复用 `RandomRequestExecutor(scope=..., state=..., save=...)` 和
`execute(operation, request_id, arguments)`。宿主提供独立会话作用域、原子持久化回调与已保存状态，
同一作用域跨执行器实例的访问由宿主串行化。创建新局时创建新作用域，读档时复用旧作用域。

本期没有接入开局触发器、运行时状态字段或秘密可见性策略。创作上下文中的随机记录只应提供给作者 LLM；
未来游戏执行器须另外控制哪些结果可供导演、角色和玩家看到，不能将作者记录直接当作新局状态。

## 验证

覆盖算法约束、数量守恒、重放、并发去重、保存失败、OpenAI/Claude 工具往返、协议字段保留、
无效调用纠正、预算和取消、提前结束后的 JSON 收尾，以及真实生成服务的编译通过、请求计数和无效 JSON 后重建服务恢复。
测试使用模拟模型响应，不依赖外部 LLM 服务。
